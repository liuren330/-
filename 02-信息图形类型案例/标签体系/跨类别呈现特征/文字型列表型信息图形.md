# 文字型/列表型信息图形（Informational / List Infographics）

**工作定义（待案例验证）**：以文字信息、条目、短段落、标题和说明为主要内容，通过列表、分组、编号、图标、卡片或网格等方式组织，使读者快速扫描、检索和理解一组信息。视觉元素通常承担导航、分类、强调或辅助解释作用。

## 1. 内容逻辑与类型边界

- 主要内容单元是条目、事实、步骤、建议、定义或知识点。
- 条目之间可按主题、重要性、流程、类别或阅读任务组织；若核心是严格的时间顺序，则更接近时间轴型。
- 列表是组织形式，不代表条目一定是统计数据；不能把装饰性编号误解为排名。
- 文字型强调文字内容为主；列表型强调并列条目结构，两者常重叠但不完全相同。

## 2. 分析维度

### A. 数据/内容逻辑
记录条目是否同质、是否共享字段、是否互斥或可重叠、排序依据是什么；区分事实、观点、步骤、建议和数据指标。

### B. 统计图形与计算
检查是否包含计数、比例、排名、评分或对比图表。若没有定量数据，不强行归类为统计图；若出现排名或百分比，核实其口径和来源。

### C. 视觉编码
分析编号、项目符号、图标、色块、分隔线、卡片、字号、字重、行距与对齐方式。检查颜色是否编码类别/状态，图标是否具备一致语义，强调色是否真正突出重点。

### D. 信息架构
常见结构为主标题 → 导语/摘要 → 分组标题 → 条目标题 → 条目说明 → 补充提示/来源。记录每条文字的信息长度、层级深度与图文比例。

### E. 视觉叙事架构
描述读者如何从标题进入，如何扫描分组与条目，重点如何被强调，结尾是否有总结/行动建议。列表型可采用线性阅读，也可采用模块化跳读。

## 4. 暂定原则与待验证问题

- 每个条目应有明确的语义单位，尽量保持条目粒度一致。
- 通过分组标题建立信息块，避免所有内容处于同一视觉层级。
- 文字可读性优先于装饰；控制单条文字长度并建立稳定的对齐规则。
- 编号仅在表达顺序、步骤或排名时使用；无序并列内容使用一致的项目符号或图标。
- 待案例验证：条目数量与版面密度、图标/插画占比、长短文本混排策略、是否存在信息优先级编码。

## 入库分类与分析规范（统一口径）

- **01｜五大类别**：视具体内容归入五类之一；文字/列表是呈现形态，不是新增一级类别。个案必须以整体主导的信息组织逻辑判定主类别；出现多种结构时，记录主类别与次要/混合特征，不得新增一级类别。
- **02｜现有标签**：待确认：文字型/列表型可作为呈现特征标签，需先判定其主导组织逻辑。未核实标签清单前，不将临时描述冒充正式标签；个案记录须填写标签及理由，未知时明确标注待确认。
- **图形特性**：记录信息目标、受众、内容单元、布局、构图、色彩、字体、图形语法、信息层级、信息密度与适用场景。
- **制作方法与流程**：按资料/数据采集 → 清洗整理 → 分类排序/统计计算 → 图形形式选择 → 视觉编码映射 → 版面设计 → 校验输出梳理；区分图面可确认事实与推测。
- **视觉编码**：说明位置、长度、角度、面积、颜色、形状、方向、纹理、连接、空间位置、尺度、文字/符号分别映射何种字段及其表达关系。
- **视觉叙事**：说明主题、阅读入口与路径、信息展开顺序、对比/转折、视觉焦点、节奏及结论传达。
- **基础数据集**：能获取且许可允许时上传至个案目录 `data/`；记录来源、格式、字段、处理步骤及视觉映射。不可获取时标注原因，不得编造或上传受限数据。
